## Part AE — Attendance exception

This plan builds the Attendance exception feature on the existing V3 schema. Punch classification remains owned by Attendance; Reporting consumes Attendance service results; the responsible-Mentor relationship belongs to Internship; finalization/reopening belongs to the period feature. Reporting must not query exception tables or entities directly.

This plan adds no attendance contract migration: V3 created `attendance_exceptions` and `attendance_exception_decisions` with the `DB-016` constraints and the append-only trigger, and the plan builds the feature on them. AE-02 adds one migration, numbered at implementation time, that extends `ck_notifications_type` with `ATTENDANCE_EXCEPTION_SUBMITTED` and `ATTENDANCE_EXCEPTION_DECIDED`, which `NOT-002` requires to request both channels; data-model C.6 lets a feature plan add codes in its own contract.

Tasks run on the part C integration branch `work/fix/architecture/schema-contracts`.

### Order of work

Tasks AE-01 through AE-06 are in [TASKS.md](TASKS.md). AE-01 through AE-03 and AE-05 can begin without B-02; AE-02 is the Intern-owned request operation. AE-04 holds responsible-Mentor authorization, decisions, marks, amendments, reversals, and actor denials. AE-04 starts after part B's authorization policy (B-02) is on main and merged into the part C branch. Each behavior task starts with a PostgreSQL/Testcontainers test and observes the intended RED before code changes. Run GitNexus impact before changing a symbol; resolve `UNKNOWN` with text search and report HIGH/CRITICAL risk before proceeding. Test Javadoc names the rule, observable failure, and derived expected value; changed public/protected members receive Javadoc in the same implementation step.

1. **AE-01 — Domain and V3 persistence.** Map the two existing V3 tables and decision history to attendance-owned domain/repository/service types; use `AttendanceExceptionEntity`, `AttendanceExceptionDecisionEntity`, `AttendanceExceptionStatus` and `AttendanceExceptionService`, not a domain class named `AttendanceException`. First add a PostgreSQL/Testcontainers integration test that uses the attendance service to persist and reload an exception with a decision-history row; it is RED because the service operation does not exist. Guard the existing DB-016/DB-017 predicates with PostgreSQL/Testcontainers probes, which pass at once because V3 already enforces them; RED applies to the application tests of this task. Keep status and latest effective decision aligned in one transaction. No B-02 dependency. Cover `AC-DB-006` and `AC-DB-011`.
2. **AE-02 — Intern requests.** Add the Intern's request for their own existing late/early violation, with reason, open-period check, one row per violation kind, and the inclusive 48-hour scheduled-end deadline. Add the `ck_notifications_type` migration so submitted and decided exception notifications can request both in-app and email delivery. First prove with a PostgreSQL/Testcontainers probe that both new codes are rejected; then add the migration. This is the Intern-owned operation and does not wait for B-02. Cover `AC-EXC-001` and `NOT-002`.
3. **AE-03 — Overdue and reminders.** Add the separate 48-hour decision deadline, idempotent scheduled/read-time overdue marking, and `NOT-011` reminder to the responsible Mentor using `SYSTEM` (in-app only, as specified by data-model C.6). An overdue item stays undecided and visible, not excused or unexcused. This task does not wait for B-02. Cover `AC-EXC-003` and `AC-ATT-009`.
4. **AE-04 — Mentor decisions, marks, amendments, reversals, and actor policy.** starts after part B's authorization policy (B-02) is on main and merged into the part C branch. Use `AUTH-012`/`ACC-026` for decision, direct mark, amendment, reversal, and refusal of other actors. Append retained decision entries; apply D31's amendment limits and period/reopen guards. Publish submissions/decisions through `NotificationService.publish` using `ATTENDANCE_EXCEPTION_SUBMITTED`/`ATTENDANCE_EXCEPTION_DECIDED`; use `SYSTEM` for overdue reminders. Keep `projectId = null`. Cover `AC-EXC-002`, `AC-EXC-003`, `AC-EXC-004`, `AC-DB-006`, and exception cells in `AC-AUTH-011`.
5. **AE-05 — Excused state in attendance results and reports.** Expose current excused state through the Attendance service; reconcile `ATT-016` counting while preserving the visible violation and excused marker in history, reports, and statistics. Reporting consumes the Attendance service and does not access exception tables. Coordinate the count reconciliation with B-03 under the shared risk below. Cover `AC-EXC-001`, `AC-EXC-003`, and `AC-ATT-006`.
6. **AE-06 — Close the Attendance exception part.** Close acceptance gaps after AE-01 through AE-05; verify requests, decisions, direct marks, history, notifications, and reporting views; run the affected attendance/reporting integration and UI gates and record actual results in `plan.md`. Cover `AC-EXC-001`–`AC-EXC-004`, `AC-ATT-006`, `AC-ATT-009`, `AC-DB-006`, `AC-DB-011`, and exception cells in `AC-AUTH-011`.

Whichever of part B and this plan's code reaches main second deletes that line and exercises its matrix cells in the same change.

### When done

The feature is ready when `AC-EXC-001`–`AC-EXC-004`, `AC-ATT-006`, `AC-ATT-009`, `AC-DB-006`, `AC-DB-011`, and exception permission cells in `AC-AUTH-011` pass for their named cases; excused state is exposed by Attendance and consumed by Reporting without cross-feature table access; notification recipients follow `NOT-011`; V3's schema supports the exception tables without an attendance contract migration; and AE-02's notification-type migration supports both designated channels.

### Not in this part

- This feature adds no attendance contract migration. It does not amend the V3 exception tables or alter any already-implemented schema predicate.
- Leave and missed-checkout correction behaviors remain in their plans; a correction may affect the early-departure classification, but an exception neither edits nor excuses a correction itself.
- `D31` allows amendment of only an exception decision note or the reason of a direct mark; outcome changes are reversals, not amendments. Do not infer any other editable fields.
- `D14` supplies the shared responsible-Mentor, overdue, retained-history and finalization decisions; `D24` sets the period grace owned by period finalization and this plan does not change it.
- Reporting never reads Attendance exception repositories/entities directly; its data remains behind the Attendance service boundary.
