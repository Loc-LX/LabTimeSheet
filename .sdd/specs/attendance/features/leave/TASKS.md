## Verification gates

- Each behavior task starts with its smallest PostgreSQL/Testcontainers test and records the expected RED reason before production edits. LV-01 also performs the C.2/C.5 read-only preflight before migration; do not access a database while writing this plan.
- Before each production symbol changes, run GitNexus impact analysis, inspect callers/processes/risk, and resolve `UNKNOWN` with text search. Report HIGH or CRITICAL before proceeding.
- Test Javadoc names the exact rule and acceptance scenario, the observable break, and the derived expected result. Add Javadoc to changed public/protected members in the same implementation step.
- Use real Spring services/repositories and PostgreSQL through Testcontainers; never H2 for PostgreSQL-specific constraints. C-05 reclassifies stored rows before adding Leave predicates and ships with code that obeys them.
- LV-04 starts after part B's authorization policy (B-02) is on main and merged into the part C branch. LV-01 through LV-03 do not wait for that policy.
- Run focused and affected attendance tests after each task. Before review, run the full Maven suite, `npm run test:ui`, `git diff --check`, and the applicable disposable E2E journey; report actual results. Do not weaken assertions or rule traces.
