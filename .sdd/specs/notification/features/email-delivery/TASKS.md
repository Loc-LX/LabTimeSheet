## Verification gates

- For every task, start with the named PostgreSQL/Testcontainers acceptance test and observe the intended RED before changing production code. ED-01 carries data-model C-07 and performs its specified read-only stored-row check before the migration.
- Before changing a production symbol, run GitNexus impact analysis, inspect callers/processes and risk, and confirm `UNKNOWN` via text search. Report HIGH or CRITICAL before editing that symbol.
- Add Javadoc to each new test naming the exact `NOT-*` and `AC-NOT-*` requirements it protects, including the observable break and hand-derived expected result. Add Javadoc alongside changed public/protected members.
- Use real Spring components at the tested boundary and PostgreSQL via Testcontainers; fake only SMTP. Do not use H2 for schema behavior.
- After the final change, run focused tests, the full Maven suite, `npm run test:ui`, the required end-to-end suite, `git diff --check`, and GitNexus graph change analysis. Do not weaken or remove existing assertions or requirement traces.
